ReShade

原始图像分辨率

效果处理分辨率
预览时可能是 1920 × 1080

软件窗口/画布分辨率
例如窗口只有 1600 × 900

中央画布只是把处理后的纹理缩放显示出来。放大、缩小和平移通常只改变显示纹理的
UV，不必重新运行 ReShade。

1.

将 Runtime 与 Swap Chain 尺寸解耦

原版逻辑是：
C++
_width

= back_buffer_desc.texture.width;

_height = back_buffer_desc.texture.height;

建议改为：
C++
_width

= working_image_width;

_height = working_image_height;

更完整一点，可以增加一个离线初始化描述：
C++
struct offline_runtime_desc
{
uint32_t width;
uint32_t height;
reshade::api::format color_format;
reshade::api::color_space color_space;
reshade::api::resource_view color_input_srv;

reshade::api::resource_view depth_input_srv;
};

然后增加类似：
C++

const offline_runtime_desc &desc);

此时 Swap Chain 只负责显示 UI，不再决定 ReShade 效果尺寸。

2.

将 COLOR 绑定到 coloroutput

ReShade FX 中：
hlsl
texture2D ColorTexture : COLOR;

原本绑定的是当前游戏 Back Buffer。官方语言参考也规定 COLOR 是只读的 Back Buffer 内
容。

GitHub

离线版需要把它改为绑定你加载的颜色纹理：
C++
runtime->set_color_input(color_output_srv);

逻辑上相当于：
COLOR semantic
↓
coloroutput.png / EXR / DDS

从 Shader 的角度看，它仍然认为自己在读取 ReShade 的 COLOR ，因此大多数 .fx 不需
要修改。

3.

将 DEPTH 绑定到 depthoutput

同理：
hlsl

texture2D DepthTexture : DEPTH;

runtime->set_depth_input(depth_output_srv);

官方定义中， DEPTH 是游戏深度信息。离线版本只需要让外部深度纹理占据这个
semantic。

GitHub

不过最好不要直接把普通 8-bit PNG 当最终深度格式。内部加载后应转换成：
R32_FLOAT

或者至少：
R16_FLOAT

例如：
C++

Width

= image_width

Height = image_height
Format = DXGI_FORMAT_R32_FLOAT

即使输入是 PNG，加载后也可以解码成浮点纹理。
