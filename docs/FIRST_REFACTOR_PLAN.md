按照这个计划完成我们的第一次重构，完成除了用户验收的1-8步，整个流程中禁止使用computer use：

按 **“状态归属 → 会话控制 → 操作与反馈 → 素材入口 → 导出 → 编辑历史 → 布局 → 批处理与 Add-on → 整体验收”** 执行。

前三步只完成主流程必需的架构调整，每一步都保持程序可运行。第五步结束时，应交付一个完整可用的“打开素材、调整效果、导出图片”流程。

三个结构边界先明确为：

| 边界               | 负责什么                          | 与其他层的关系                           |
| ---------------- | ----------------------------- | --------------------------------- |
| **B1：会话生命周期**    | 启动、连接、输入应用、重载、恢复、取消和释放        | Core 负责规则；WinUI 管理显示表面；MCP 调用相同规则 |
| **B2：编辑状态与应用偏好** | 当前素材、效果、预设、输出规格，以及独立的应用默认设置   | 明确区分正在编辑的配置、已经应用的配置、已经保存的预设       |
| **B3：操作与结果**     | 参数修改、切图、预设、导出等操作，以及互斥、错误、状态通知 | WinUI 与 MCP 通过共同入口操作；界面负责呈现结果     |

**1. 先建立状态模型，落实 B2 的基础**

设计三类状态：

- **编辑状态**：当前素材、深度关联、效果参数、预设及输出规格。
- **运行状态**：宿主实际使用的输入、配置版本、连接和编译情况。
- **应用偏好**：默认目录、界面布局、预览传输偏好及自动化配置。

同时明确哪些修改即时生效，哪些需要“应用”，哪些需要“保存预设”。旧配置文件通过兼容迁移读取，保留用户现有路径和偏好。

**本步要求：** 每项数据只有一个明确的归属；设置写入磁盘不能直接代表渲染已经应用。先预留编辑历史接口，完整撤销系统放到第六步。

**验收：** 修改输出尺寸后，能够准确表示“待应用”；应用失败不会把新配置标记为生效；重新启动后已有配置正确恢复。

**2. 统一会话控制，落实 B1**

把 WinUI 和独立 MCP 重复的启动、切图、重建、恢复逻辑逐步收进 Core。迁移顺序为：

启动和关闭 → 输入切换 → 重载和重建 → 恢复与取消。

附着 MCP 使用正在运行的 WinUI 会话；独立 MCP 创建自己的会话实例，两者复用同一套控制逻辑。WinUI 保留预览表面的创建、显示和交互职责。

**本步要求：** 切换输入和重建时携带状态版本；旧请求返回后不能覆盖较新的状态。重建应恢复当前已应用的编辑状态，避免直接从旧预设文件恢复而丢失调参。

**验收：** 三种入口——WinUI、附着 MCP、独立 MCP——在切图、尺寸变化、取消和恢复场景下行为一致；关闭后进程、连接和显示资源正常释放。

**3. 统一操作入口与错误结果，落实 B3，同时完成高优先级问题“状态与反馈”**

参数修改、预设、切图和导出逐步经过共享操作层。每次操作统一返回成功、警告、取消或失败，以及受影响的素材和恢复信息。

界面分别表达素材状态、运行状态和任务状态，再组合成用户能理解的提示：

- 未打开素材：显示打开入口。
- 监听中：显示等待游戏输出。
- 编译中：显示进度或正在处理的内容。
- 失败：显示原因和适用的重试、定位文件、查看详情操作。
- 没有批处理任务：收起批处理进度区域。

**本步要求：** 不再由各个按钮自行拼接状态文字；通用命令异常必须进入统一反馈。正常黑色作品继续允许导出，黑色检测保持警告语义。

**验收：** 保存预设、重载、切图和导出失败都能直接看到原因；空画布与真实黑色作品可区分；不会同时用含糊的“Ready”和“Disconnected”描述整个应用。

**4. 重做素材入口，完成高优先级问题“工作流程隐藏在设置里”**

主界面提供“打开素材”和“监听游戏输出”，将当前图片、深度关联、当前预设放到工作区。Settings 保留应用偏好和高级配置。

两种输入来源共用后续编辑和导出流程。复用现有素材配对能力，匹配不明确时允许用户手动关联；缺失或损坏输入就地提示。

**本步要求：** 打开、校验、应用输入是一套完整操作。失败时保留上一份有效编辑状态，并明确说明新素材未成功打开，不能把旧画面当作新素材显示。

**验收：** 首次使用无需进入 Settings 就能打开图片、关联深度并开始调参；用户随时知道当前处理哪张图、是否正在监听更新。

**5. 统一导出，完成高优先级问题“双按钮容易误选”**

主界面只保留一个“导出图片”入口。导出面板显示目标文件、最终尺寸和文件冲突策略，高级选项说明截图插件兼容方式和预热参数。

计划以经过兼容回归验证的 ReShade 截图路径作为默认方式，保留直接 PNG 路径作为明确的高级选项。两条路径不能静默互换。

**本步要求：**

- 导出绑定已应用的素材和效果状态。
- 有待应用配置时，明确提供“应用后导出”，不能悄悄使用旧配置。
- 导出前完成必要参数提交，防止最后一次滑块修改尚未到达宿主。
- 保留已有编译、贴图、深度、文件完整性及输入变化检查。
- 完成后提供打开图片和所在文件夹的操作。

**验收：** 用户无需理解底层截图 API 就能正确导出；导出内容与已应用的编辑状态一致；损坏效果不能被标记成功，失败不会破坏已有成品。

**到这里作为第一个交付节点：三个结构边界完成主流程接入，三个高优先级问题全部通过验收。**

**6. 加入编辑历史，完成中优先级问题“编辑与保存语义不完整”**

在第三步的共享操作层上加入撤销、重做、参数复位、未保存标记、保存和另存预设。

具体规则提前固定：

- 一次滑块拖动实时预览，但只产生一条撤销记录。
- 只有成功应用的修改进入历史。
- 默认切图保留当前效果调整；切图本身不等于预设修改。
- 加载另一份预设或关闭窗口时，处理未保存修改。
- 导出图片与保存预设分别执行。
- MCP 修改也更新界面和修改标记，可撤销操作进入同一历史。

**本步要求：** 保存失败不清除未保存标记；撤销回已保存内容时正确恢复标记。第三方 Add-on 的不透明状态按能力处理，界面不承诺无法实现的撤销。

**验收：** 连续调参、撤销、重做、保存、另存和切图之后，参数、画面及修改标记一致。

**7. 调整画布与布局，完成中优先级问题“操作不可发现、窗口适应性不足”**

在前面已经稳定的操作模型上拆分效果面板、画布和素材面板，再调整布局：

- 顶部保留主要操作，次要命令进入溢出菜单。
- 效果侧栏可调整、折叠，图库和任务区域按需展开。
- 画布提供适应窗口、100%、缩放比例和前后对比。
- 补齐快捷键、焦点顺序、图标按钮名称及主题支持。

**本步要求：** 明确 100% 的像素含义；降采样预览显示实际预览分辨率。临时前后对比只改变预览，不修改预设或导出状态。沿用已有缩放几何和资源管理成果。

**验收：** 在约定的最小窗口及不同 DPI 下，主命令始终可达；缩放、拖动、对比不会改变输出尺寸和成品状态。

**8. 完善批处理和 Add-on，完成第三个中优先级问题**

这一项分两小步实施。

先完成批处理：导出前显示全部或选中范围、有效与无效数量、目标目录、命名和冲突策略；运行时显示逐项状态；完成后支持定位结果、重试失败项和恢复任务。

再整理 Add-on：常用控制优先展示，原生界面保留兼容入口，ImGui 捕获和技术诊断默认收起。

**本步要求：** 批处理启动时固定本次使用的效果和输出设置。区分“指纹匹配后复用”“用户选择跳过”“本次成功导出”，不能把它们混成成功计数。取消或结束后恢复原编辑上下文。

**验收：** 用户执行前知道会处理哪些文件，执行后知道每项结果；旧缓存仍须严格匹配；普通 Add-on 调参无需经过调试区域。

**9. 完成整体验收并整理发布包**

最终按完整用户流程验证，而不只检查各个按钮：

| 场景               | 必须满足的要求         |
| ---------------- | --------------- |
| 首次使用             | 打开素材、调参、导出可独立完成 |
| 输入异常、损坏效果        | 明确失败，不输出旧画面冒充成功 |
| 合法黑色作品           | 可以导出，提示保持警告     |
| 未保存修改、重建会话       | 状态和参数不会意外丢失     |
| WinUI 与 MCP 混合操作 | 参数、忙碌状态及操作结果同步  |
| 批处理取消与恢复         | 结果可追踪，缓存校验仍有效   |
| 窄窗口、高 DPI、键盘操作   | 主要操作可达，画布可用     |

每一步应形成可独立审查和回退的变更，并进行git版本管理，运行与该步骤相关的测试；最终复用现有输出正确性、D3D、MCP 和发布校验做整体验收。涉及接口契约变化时同步版本及兼容性检查。真实驱动变更测试继续按原安排，等待本机 NVIDIA 驱动更新。

**第一个实施任务应是第 1 步：确定状态归属、配置迁移和“编辑／应用／保存”的规则。** 这些规则确定后，会话、导出和撤销系统才有一致的依据。
