# 稳定性修复计划

记录日期：2026-11-02。范围：Offline ReShade 原生宿主、WinUI、Core 与 MCP。

## 第一步：输出正确性（已完成，0.8.1）

- 导出前验证预设要求启用的效果是否编译、创建成功，依赖贴图是否加载成功。
- 深度数据必须尺寸正确、数值有限且处于支持的归一化范围 [0, 1]。
- 实时输入变更分辨率时重建会话，禁止以旧尺寸或旧输入假报成功。
- 批处理续跑使用内容哈希及完整渲染状态；损坏效果与不匹配旧输出不能跳过验证。
- 全黑只提示，不阻止合法黑色作品；失败明确返回错误并保留已有成品。
- 验收：异常输入或损坏的启用效果不能标记为成功导出，批处理不能复用不匹配的旧结果。

2026-11-02 验证通过：

- Core 测试：输出保护、RPC 取消、实际帧预热、批处理续跑、编辑锁与取消。
- 原生 CLI 与独立 MCP 集成：正常渲染、缩放、参数编辑、干净截图、混合分辨率批处理。
- 输出正确性回归：损坏的启用 FX、缺失贴图、NaN / Infinity / 越界 / 截断深度均失败；失败保留已有输出；合法全黑成功并提示；未启用的损坏 FX 不阻止导出。
- 实时输入从 320×240 变为 480×320 后自动重建并以新尺寸导出；损坏替换文件不能导出旧画面。
- 批处理仅在状态和内容完全匹配时续跑；全局效果开关、源图、FX、贴图变化均使缓存失效，包含文件大小和时间戳未变的源图内容变化。删除贴图不能复用旧结果。
- 同一套正确性回归通过真实 WinUI 会话和 MCP 附着执行；修复重建时共享纹理残留及关闭后的预览回调，窗口正常退出。

可复现入口：`tools/build_offline_release.ps1 -RunIntegrationTests`；已启动的 WinUI 会话可用 `tests/run_output_correctness.py --package <发布目录> --work <独立测试目录> --session <会话 ID>` 验证。测试会切换会话输入，请使用专门的测试窗口。

## 第二步：D3D 与缩放（已完成，0.8.2）

已有适配窗口、拖动、1–16 倍预览缩放和指定输出尺寸。本步维护补齐这些操作的资源与故障边界：主预览共享纹理同步、宿主与 WinUI 显卡匹配、固定 viewport 内取样、设备故障恢复及大图预算；保留正常操作方式。

- 显卡身份协商、共享纹理同步、设备丢失重建及 CPU 预览降级。
- 高 DPI、极端宽高比、高倍率缩放边界，以及大图内存预算。
- 预览缩放和最终输出尺寸分别验证。
- 验收：预览缩放不改变成品尺寸或像素；共享纹理不可用时明确提示并降级；设备失效后有界重建，无法恢复则明确失败；超限尺寸在分配大块资源前报错。

2026-11-03 实现与验证：

- 主预览增加 keyed mutex 同步；WinUI 按宿主的 adapter LUID 创建显示设备。完成帧复制到本地缓存，生产者忙时仍能重绘和缩放。
- 缩放改为固定 viewport 内的纹理取样；用实际图像而非留白区域限制拖动。补充 SwapChainPanel 的 DIP/物理像素变换，修复实际窗口中发现的高 DPI 二次放大与右侧裁切；CPU/GPU 使用相同显示几何。
- 显示资源失败时最多连续重建 3 次，之后转 CPU 预览；Add-on GPU 面板失败则显示不可用。渲染设备失败保持诊断 RPC 可用，禁止导出陈旧画面；Core/WinUI 在 30 秒内最多恢复 3 次，保留全局效果状态，持续失败明确报错。
- 源图与输出采用单边 16384、总计 64×1024² 像素上限，并检查可用系统内存与显存预算。预览单独限额；默认 CPU 预览最长边 1920，不改变成品尺寸。
- D3D 实机测试通过：同显卡身份匹配、80 帧连续同步像素、缓存重绘、超大缩放、留白、无效几何、DPI 变换、尺寸切换与资源释放。
- Core、原生 CLI、独立 MCP 与实际 WinUI 附着回归通过；覆盖单像素边长、极端宽高比、超限源图/输出、CPU 降级、设备故障注入及恢复次数上限。
- Windows 窗口实测通过：缩放、拖动、复位、最大化、GPU/CPU 双向切换；1600×800 成品逐像素一致。另用缺失预览桥 DLL 的独立测试副本验证三次失败后自动转 CPU，输出仍逐像素一致。测试窗口全部正常关闭。

验证设备：本机 NVIDIA GeForce RTX 4070 Ti SUPER。故障注入验证恢复流程，未主动重置系统显卡驱动；真实驱动重置、跨不同厂商双显卡和多显示器切换仍需第三步硬件矩阵验证。显存预算是保守估算，不能预知任意第三方 FX 的全部资源需求。

复现入口：`tools/build_offline_release.ps1 -RunIntegrationTests`（包含 `tests/OfflineReShade.Graphics.Tests.vcxproj`、`tests/run_d3d_recovery.py` 及第一步回归）。真实 WinUI 测试使用独立开发包，通过 `winapp run --with-alias --debug-output` 启动，使故障注入环境仅作用于该测试进程。

实现依据：[共享纹理同步与 abandoned 状态](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgikeyedmutex-acquiresync)、[viewport 有效范围](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_viewport)、[交换链矩阵变换](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgiswapchain2-setmatrixtransform)、[显存预算查询](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo)。

## 第三步：维护基线（0.8.3）

2026-11-03 实现范围：

- 固定当前 ReShade 上游提交、tree、最近发布标签和 11 个子模块提交；固定内部 RPC/ABI、.NET SDK/运行时，强制 NuGet 锁定还原。构建次数不再改变原生版本号。
- CI 固定 Action 提交和 Windows runner 代际，分离基线检查与验证发布任务；保留失败诊断，只在完整回归与 ZIP 校验成功后上传程序包。
- 宿主/DLL、WinUI/宿主、MCP/broker 和预览桥增加版本握手；错误组件在操作前明确失败，预览桥沿用 CPU 降级。
- MCP 增加只读 `get_diagnostics`，统一版本、运行状态、来源信息和核心文件完整性诊断。
- 发布清单记录源码快照（包含未提交文件）、依赖锁哈希、实际工具链和测试命令结果；校验发布包所有文件及 ZIP 哈希。
- 验证入口、接口升级规则和提交发布流程见 [维护基线](MAINTENANCE.md)。代码仍需提交并推送后，才能获得 GitHub 托管 runner 的执行结果；本机回归不能替代远端 CI 结果。

按用户 2026-11-03 的安排，驱动变更测试等待本机下一次 NVIDIA 驱动更新后进行；本步不投入驱动重置、跨厂商双显卡及其他硬件矩阵扩展。现有软件故障回归继续执行，不代表真实驱动变更已验收。
