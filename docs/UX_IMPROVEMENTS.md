# 目前最需要改善的地方

记录日期：2026-11-03。基于 Offline ReShade 0.8.3 的源码与实际窗口审查。状态：待实施建议。以下观察来自当前实现和测试窗口，尚不是用户可用性测试结论。

目标是让用户顺畅完成“打开素材 → 调整效果 → 导出”，并始终知道当前素材、预设修改状态及输出结果。对应的底层调整见[架构修改意见](ARCHITECTURE_RECOMMENDATIONS.md)。

## 问题与调整建议

| 优先级 | 当前问题 | 建议调整 |
|---|---|---|
| 高 | 打开图片、关联深度和选择预设藏在 Settings 中，设置页首先显示 MCP session ID | 主界面提供打开素材与监听游戏输出入口，显示当前素材、深度关联和预设；技术配置进入高级设置 |
| 高 | ReShade Shot 与 Save PNG 并列，要求用户理解实现区别 | 合并为一个导出图片入口，将导出方式及截图插件兼容选项放入导出面板；统一批处理入口 |
| 高 | 未加载素材时画布纯黑，同时出现 Disconnected 和 Ready；失败原因经常只写日志 | 明确展示未打开素材、等待输入、编译中、预览中及失败状态；错误附带原因与恢复操作 |
| 中 | 缺少完整撤销、重做、预设未保存标记；设置保存与渲染生效时机不直观 | 加入编辑历史、未保存标记及另存预设；需要重新加载的设置显示待应用状态 |
| 中 | 较窄窗口下顶部命令被挤出；效果侧栏固定宽度；缩放主要依赖手势 | 工具栏支持溢出，侧栏可调整和折叠；提供适应窗口、100%、比例和前后对比入口 |
| 中 | 批处理直接取全部有效条目，范围及跳过原因不够直观；Add-on 调试内容占据常规空间 | 导出前展示范围、数量、目录及冲突策略，完成后显示逐项结果；调试内容默认收起 |

## 一 素材入口与工作模式

当前 Settings 同时承载工作素材和应用配置。建议主界面直接支持打开图片、关联深度、选择预设，并复用已有素材配对逻辑。空画布展示打开素材的操作入口；监听模式下区分等待游戏输出与输入损坏。

Real Time 与 Gallery 当前通过开关切换。建议改为明确的来源选择，说明监听游戏导出与浏览已有图片的差别，使用户知道后续输入是否会自动更新。

验收：首次使用无需阅读说明即可打开素材；当前文件、深度关联状态和输入来源随时可见。

## 二 统一导出入口

当前两个按钮均用于完整分辨率导出，其中 ReShade Shot 经过 ReShade 截图 API 并涉及截图插件事件。断开连接时 Save PNG 可以点击，ReShade Shot 却被禁用。这种差异容易影响用户选择，不能简单归因于用户点错按钮。

建议提供一个“导出图片”主入口，明确默认方式，在选项中解释截图插件事件与直接 PNG 导出的用途。默认方式应结合现有 Add-on 兼容需求验证后确定，不静默改变插件行为。

导出面板展示目标文件、输出尺寸和覆盖策略；预热帧数等参数进入高级选项。导出完成后提供打开文件及所在文件夹的操作。批量导出复用相同设置模型。

验收：用户无需理解底层 API 就能导出；两条导出路径仍受现有编译、贴图、深度和文件完整性检查保护。

## 三 状态与错误反馈

未加载素材、等待输入、加载或编译、可编辑、导出中和失败需要清晰呈现。连接状态作为辅助信息，不与作品状态共同形成含糊的 Ready 提示。无批处理任务时收起常驻的批处理进度区域。

错误直接说明发生了什么、影响哪项操作，并提供适用的重试、定位素材或查看详情入口；日志保留技术细节。正常黑色作品仍允许导出，亮度检测只作提示。空状态使用说明及操作按钮，与真实黑色图像区分。

验收：保存预设、重载、切图及导出失败都不只留下隐藏日志；用户能区分警告、取消和失败。

## 四 编辑与预设

加入撤销、重做、参数复位、预设未保存标记以及保存和另存操作。一次滑块拖动视为一次历史操作，避免每个预览更新都占据撤销步骤。切换素材或预设时明确处理未保存修改。

输入尺寸等字段应即时验证；已写入设置文件但尚未应用到宿主的配置明确显示“待应用”。任意 Add-on 内部状态是否支持撤销取决于其接口能力。

验收：能够撤销一次调参，准确知道当前预设是否已保存，并区分正在编辑的配置和已生效的配置。

## 五 画布与自适应布局

保留已有适应窗口、缩放及拖动能力，补充可发现的控件。适应窗口与源图 100% 像素查看分别表达，预览缩放比例与最终输出尺寸分别展示。已有全局效果开关可作为前后对比能力的基础。

以画布为中心，顶部放打开素材、预设、撤销和导出；效果侧栏展示正在使用的效果与参数，图库及任务队列可以收起。次要命令进入溢出菜单，侧栏允许调整宽度。随后统一快捷键、焦点顺序、图标按钮名称及主题资源，并验证高 DPI 和高对比度。

验收：在约定的最小窗口和不同 DPI 下，主命令可达、画布可用；缩放不会改变输出尺寸；手势功能有可见入口。

## 六 批处理与 Add-on 信息层级

批处理执行前展示全部或选中范围、有效与无效条目数量、目标目录、命名和冲突策略。执行后展示每项成功、失败、复用或跳过的原因，并提供重试失败项和恢复任务的入口。继续遵守已有缓存指纹校验规则。

Add-on 常用控制、原生兼容界面和诊断信息分层展示。保留原生界面入口；ImGui 捕获调试等内容默认收起并移入诊断区域，避免与日常参数调整争夺空间。

验收：用户在执行前知道会处理哪些文件，完成后能找到结果及失败原因；普通调参无需穿过调试信息。

## 实施顺序

1. 完成打开素材、状态提示、错误反馈与统一导出的主流程，同时落实必要的 Core 状态调整。
2. 完善编辑历史、预设保存语义、画布控制、自适应布局及批处理任务体验。
3. 整理 Add-on 与诊断层级，统一视觉细节、快捷键及无障碍支持。

第一轮验收重点：无需说明完成首次导出；当前素材、输出尺寸、目标位置和预设修改可见；空画布与黑色作品可区分；失败不会只进入日志；WinUI 与 MCP 相同操作的状态和结果一致。
